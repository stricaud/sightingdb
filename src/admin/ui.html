A namespace is a path, so feeds/misp/ips browses like folders: folder means other namespaces sit underneath it, namespace means it holds values of its own, and a path can be both. hot stays in memory; warm is written out and dropped once untouched for the seconds beside it; cold is dropped at the next sweep. Evicted data is read back automatically when it is next used. Storage settings belong to the whole top-level namespace, named after the control, because that is one file paged in and out as a unit — changing them for myorg/one changes myorg and everything under it. A window shown greyed is the configured default; type over it to give this one its own.

Export STIX


Values SightingDB can type — addresses, domains, URLs, hashes, email addresses — plus anything carrying a stix-type: tag. Anything else is left out and counted.


The same, plus every remaining value as x-sightingdb-value, flagged x_sightingdb_untyped so a consumer can filter them. STIX 2.1 has no plain-text observable, so this is a custom type rather than a standard one.

Add values

Leave the TTL blank to keep whatever expiry a value already had, or set 0 to clear it. Leave the time blank to record the values as seen now. Writing a namespace that does not exist creates it. Tags are merged with whatever each value already carried, and are what the STIX export uses to say what a value is — see the tag vocabulary in the README.
